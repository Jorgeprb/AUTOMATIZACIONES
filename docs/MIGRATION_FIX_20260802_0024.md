# Corrección de la migración 20260802_0024

## Causa raíz

La migración `20260729_0022` creó la FK de
`phone_provisioning_orders.clinic_id` sin indicar un nombre. La revisión
`20260802_0024` intentaba eliminarla usando el nombre automático
`phone_provisioning_orders_clinic_id_fkey`.

En bases donde SQLAlchemy aplicó su convención de nombres, donde hubo una
recreación anterior o donde la FK no existe, ese nombre no coincide y
PostgreSQL devuelve `UndefinedObject`.

## Corrección

La revisión `20260802_0024` sigue siendo la misma revisión no aplicada, pero
ahora consulta `pg_constraint`, `pg_class`, `pg_namespace` y `pg_attribute` para
encontrar cualquier FK real que conecte exclusivamente:

```text
phone_provisioning_orders.clinic_id -> clinics.id
```

La elimina por su nombre real, si existe, convierte la columna a nullable y
crea una FK explícita y estable:

```text
fk_phone_provisioning_orders_clinic_id_clinics
ON DELETE SET NULL
```

No se usa `alembic stamp`, no se cambia ninguna revisión ya aplicada y se
mantiene una sola cabeza `20260802_0024`.

## Reintento en el VPS

El fallo ocurrió dentro de DDL transaccional de PostgreSQL, por lo que la
revisión fallida se revierte. Después de sustituir el archivo:

```bash
cd /opt/AUTOMATIZACIONES

docker compose -f docker-compose.prod.yml --env-file .env.production \
  build --no-cache migrate api

docker compose -f docker-compose.prod.yml --env-file .env.production \
  run --rm --entrypoint alembic migrate current

docker compose -f docker-compose.prod.yml --env-file .env.production \
  run --rm migrate

docker compose -f docker-compose.prod.yml --env-file .env.production \
  run --rm --entrypoint alembic migrate current
```

El último comando debe mostrar `20260802_0024 (head)`.
